# Data Format

The app reads two JSON files from `public/data/`, generated by the scripts in
[`scripts/`](../scripts/README.md). They are joined in the app by
`(section key, sloka number)`.

## `manifest.json` — audio structure

Describes which slokas and bundles exist in each mode and which encoded clip
each maps to. Generated by `build_audio_manifest.py`.

```jsonc
{
  "schemaVersion": 2,
  "encoding": { "codec": "aac", "bitrate": "64k", "channels": 1 },
  "languages": ["sanskrit", "tamil", "telugu", "kannada", "malayalam", "hindi", "english"],
  "sections": [
    {
      "id": "section_dhyanam",
      "key": "dhyanam",
      "name": "Dhyānam",
      "order": 1,
      "tutorial":    [ /* one entry per individual sloka */ ],
      "nonTutorial": [ /* one entry per bundle */ ]
    }
  ]
}
```

Each item in `tutorial` / `nonTutorial`:

| field      | meaning                                                            |
|------------|--------------------------------------------------------------------|
| `start`    | first sloka number covered                                         |
| `end`      | last sloka number covered (`== start` for a single sloka)          |
| `enabled`  | `false` when no audio exists yet (shown as "coming soon")           |
| `audioKey` | opaque filename stem under `public/audio/<mode>/<audioKey>.m4a`     |
| `duration` | clip length in seconds                                              |
| `note`     | human note (e.g. "combined clip", "missing file")                  |

Tutorial items are usually one sloka; a few are combined clips the teacher could
not split (e.g. Namalu `8–12`), where `start != end`. Non-tutorial items are
always bundles.

## `text-content.json` — sloka text

Per-sloka text in each language. Generated by `build_text_skeleton.py`, then
filled in by hand from the teacher's script.

```jsonc
{
  "schemaVersion": 2,
  "languages": ["sanskrit", "...", "english"],
  "sections": [
    {
      "key": "dhyanam",
      "name": "Dhyānam",
      "slokas": [
        {
          "number": 1,
          "text": {
            "english": "transliteration here (pronunciation, not meaning)",
            "sanskrit": "...", "tamil": "...", "telugu": "...",
            "kannada": "...", "malayalam": "...", "hindi": "..."
          }
        }
      ]
    }
  ]
}
```

The `english` field is transliteration (a pronunciation guide), not a
translation. Each line is separated by `\n`; the app keeps every authored line
on its own row and scales the font so the verse shape is identical on every
device.

A value like `[... to be added]` is treated as empty and shows "Text coming
soon" in the UI, so placeholders never display as real text.
